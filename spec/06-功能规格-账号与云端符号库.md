# 06 功能规格 · 账号与云端符号库（F4）

- 对应需求：FR-4.1 ~ FR-4.5
- 目标：每个同学用**自己的账号**登录，符号库**分别存储在各自账号下**，换电脑也能取回。

## 1. 技术方案

**统一使用腾讯云开发 CloudBase**（认证 + 文档数据库 + Web SDK），不再保留多套后端：

- 免费额度对课程规模够用（实测环境为个人版 4 万资源点/月）；无需购买/运维服务器，与 GitHub Pages 静态托管共存；
- 前端经 `@cloudbase/js-sdk` 直连（SDK 设计为前端公开调用，权限由数据库安全规则兜底，前端不含密钥）；
- SDK 体积大，`src/modules/cloud/client.ts` 用动态 import 拆 chunk，只在启用云端时加载。

> 历史：班级自建服务器方案（`server/class-server.mjs`，局域网零云账户）已于 2026-10-19 下线，
> 前端不再探测 `/api/ping`；如需找回可从 git 历史（commit 28cfba2 前后）恢复。

## 2. 注册与登录流程（实测约束，2026-10-19，新版 CloudBase / authentication-v2）

① **不允许「用户名+密码」直接注册**——注册必须走邮箱验证码三步：

```js
const v = await auth.getVerification({ email })                      // 1. 发验证码
const { verification_token } = await auth.verify({                   // 2. 校验
  verification_id: v.verification_id, verification_code: code,
})
await auth.signUp({ email, verification_code: code, verification_token, password, name })  // 3. 注册（自动登录）
```

② 登录：`auth.signIn({ username, password })`，username 可填**邮箱**/手机号/用户名。

③ 用户名为可选字段，服务端强制格式 `^[a-z][0-9a-z_-]{5,24}$`（2026-10-19 实测：中文/大写开头/
纯数字均被拒，报 `invalid SignUpRequest.Username: value does not match regex pattern`）——所以注册必须
用邮箱收验证码，用户名只是登录别名。前端注册时统一转小写、按该正则预校验后传入；**学号等纯数字
账号由前端自动加 `s` 前缀**（如 `20230101` → `s20230101`），注册与登录两侧同一转换，学生无感。

④ 网关按 **Web 安全域名**拦截浏览器来源（2026-10-19 实测）：未配置的域名一律 403 且无 CORS 头，
浏览器侧表现为 `Failed to fetch`。实测：localhost 放行、`hqj00.github.io` 未配置时 403。
**必须在控制台配置 Web 安全域名**：应用管理 → 对应 Web 应用 → 安全域名（或 环境配置 → 安全控制），
添加 `hqj00.github.io`（本地调试加 `localhost`）。

⑤ v3 SDK 错误形态不统一（有的 throw、有的返回 `{ data, error }`），`auth.ts` 的 `callAuth` 统一按两种形态处理。

⑥ **邮箱/用户名双通道登录（同一账号）**：注册（邮箱验证码三步）时可同时 `signUp({ ..., username })`
绑定用户名；此后登录表单填邮箱或用户名都解析到同一 uid，符号库自然共享。界面：登录页账号框
占位提示「邮箱或用户名」；注册页提供「用户名（选填）」。控制台需同时开启「邮箱」与「用户名密码」
两种登录方式。

## 3. 数据模型与安全

集合 `symbol_libraries`：**一个用户一条文档**，`_id = 用户 uid`：

```json
{ "owner": "<uid>", "symbols": [SymbolRecord…], "updatedAt": 1718000000000 }
```

权限（建集合时选「读取和修改本人数据 [PRIVATE]」，或自定义安全规则）：只允许本人读写本人文档。

## 4. 同步策略

```
未登录（本地模式）→ 点页头「登录云账号」→ /login 注册或登录
→ 登录成功：拉取云端库 ↔ 本地库按 id 合并（并集，云端优先）→ 写回本地并推送合并结果到云端
→ 之后库的每次变更（入库/删除/导入）防抖 800ms 自动推送云端
→ 退出登录：保留本地库，停止同步
```

- **降级**：未配 `VITE_TCB_ENV` → 纯本地模式（登录页显示提示，其余功能不受影响）；云端拉取/推送失败 → 本地仍可用。
- 页头账号区：未登录显示「登录云账号」；已登录显示账号 + 「退出」。

## 5. 控制台配置步骤（教师/部署者执行）

1. 开通**云开发 CloudBase**，新建环境，记录**环境 ID**；
2. 身份认证 → 登录方式：开启**「用户名密码登录」和「邮箱登录」**（缺后者发不出验证码，报 `provider email not found`）；
3. 文档型数据库：新建集合 `symbol_libraries`，权限选「读取和修改本人数据 [PRIVATE]」；
4. **Web 安全域名**（应用管理 → Web 应用 → 安全域名，或 环境配置 → 安全控制）：添加 `hqj00.github.io`
   （漏配则 Pages 上所有云端请求 403，浏览器报 `Failed to fetch`）；
5. GitHub 仓库 → Settings → Secrets and variables → Actions → **Variables** → 新建 `VITE_TCB_ENV` = 环境 ID
   （VITE_ 变量是构建期公开值，放 Variables 而非 Secrets 即可；`.env` 不入库，CI 构建从仓库变量注入）；
6. `git push` —— GitHub Actions 自动重新构建部署。

## 6. 环境变量

| 变量 | 说明 |
|------|------|
| `VITE_TCB_ENV` | CloudBase 环境 ID（前端构建期公开变量；权限由数据库安全规则兜底） |

## 7. 验收用例

| # | 操作 | 期望 |
|---|------|------|
| 1 | 未配 VITE_TCB_ENV 启动 | 应用正常工作，登录页显示本地模式提示 |
| 2 | 邮箱注册（收验证码） | 注册成功自动登录；控制台用户列表出现该用户 |
| 3 | A 账号入库符号 → 退出 → 登 B 账号 | B 看不到 A 的符号（PRIVATE 隔离） |
| 4 | 登录前本地有 3 个符号，云端有 2 个不同符号 | 登录后合并为 5 个，云端同步为 5 个 |
| 5 | 登录状态入库新符号 | 约 1s 后云端文档更新（防抖） |
| 6 | 断网登录 | 提示云端不可用，本地模式正常 |

## 8. 演进

- 教师端：只读拉取本班所有学生的符号库（另开管理员规则或云函数聚合）；
- 符号库容量：单文档有大小上限，超出时提示导出备份；
- 登录态持久化由 SDK 处理（localStorage 存凭据），长期免登。
