# 06 功能规格 · 账号与云端符号库（F4）

- 对应需求：FR-4.1 ~ FR-4.6
- 目标：每个同学用**自己的账号密码**登录，符号库**分别存储在各自账号下**，换电脑也能取回。

## 1. 技术选型：两种后端方案（按部署条件二选一）

| 方案 | 适用 | 成本 |
|------|------|------|
| **A. 班级自建服务器**（`server/class-server.mjs`） | 课堂局域网、教师机可常开；**不需要注册任何云账户** | 零成本、零注册；Node 内置模块（http/crypto/文件存储），无外部依赖 |
| **B. 腾讯云开发 CloudBase** | 学生在校外/家里也要访问 | 免费额度；需注册腾讯云并实名认证 |

前端启动时自动探测：`GET /api/ping` 通 → 方案 A；否则若配了 `VITE_TCB_ENV` → 方案 B；都不行 → 本地模式。
**两种方案对界面的表现完全一致**（同样的注册/登录/同步流程）。

## 2. 方案 A：班级自建服务器

### 2.1 运行方式

```bash
npm run build            # 生成 dist/
npm run class-server     # 启动在 8788 端口
```

教师机防火墙放行 8788 后，学生浏览器访问 `http://<教师机IP>:8788`（同端口同时托管应用与 API，
同源无跨域；GitHub Pages 版本探测不到 `/api/ping`，自动保持本地模式）。

### 2.2 API 契约

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/ping` | 探测；返回 `{ ok: true }` |
| POST | `/api/auth/register` | `{username, password}`；用户名 2~20 位、密码 ≥6 位；重复注册 409 |
| POST | `/api/auth/login` | 返回 `{ token, username }`；错误 401 |
| GET | `/api/auth/me` | `Authorization: Bearer <token>`；恢复登录态 |
| GET | `/api/library` | 同上鉴权；返回 `{ symbols: [...] }` |
| PUT | `/api/library` | 同上鉴权；整体写入该账号的符号库 |

### 2.3 存储与安全

- 数据目录 `data/`（已加入 .gitignore，不入库）：`users.json`（用户名→scrypt 加盐哈希，**不存明文密码**）、
  `tokens.json`（会话凭据，重启服务不掉线）、`libraries/<用户名>.json`（每人一个文件，天然隔离）。
- 账号隔离由服务端强制：`/api/library` 只读写当前 token 对应用户的文件，任何账号拿不到他人数据。

## 3. 方案 B：腾讯云开发 CloudBase

> **实测约束（2026-10-19，新版 CloudBase / authentication-v2）**：
> ① **不允许「用户名+密码」直接注册**——注册必须走邮箱验证码三步（`getVerification` → `verify` → `signUp`），
> 登录用 `auth.signIn({ username, password })`（username 可填邮箱/手机号/用户名）；
> ② 用户名为可选字段，且规则不允许纯数字（学号不能直接当用户名，建议直接用邮箱登录）；
> ③ 新版控制台**没有"安全域名"配置**（旧版文档概念，已实测不需要）；
> ④ v3 SDK 的错误形态不统一（有的 throw、有的返回 `{data, error}`），前端统一按两种形态处理。
> 因此注册流程为：**输入邮箱 → 发送验证码 → 输入验证码 + 密码 → 注册并自动登录**；登录为邮箱 + 密码。
> 控制台需开启：身份认证 → 登录方式 →「用户名密码登录」**和「邮箱登录」**（缺后者发不出验证码，
> 报 `provider email not found`）。

- 免费额度对课程规模够用；无需购买/运维服务器，与 GitHub Pages 静态托管共存；
- 内置「用户名 + 密码」认证方式；文档数据库按安全规则做 per-user 隔离；
- 与项目已有的腾讯云 SCF 代理（server/ai-proxy.scf.cjs）同生态。

## 2. 数据模型与安全

集合 `symbol_libraries`：**一个用户一条文档**，`_id = 用户 uid`：

```json
{ "owner": "<uid>", "symbols": [SymbolRecord…], "updatedAt": 1718000000000 }
```

安全规则（控制台配置）：只允许本人读写本人文档。

```json
{
  "read": "auth.uid != null && doc._id == auth.uid",
  "write": "auth.uid != null && doc._id == auth.uid"
}
```

## 3. 交互流程

```
未登录（本地模式）→ 点页头「登录云账号」→ /login 注册或登录
→ 登录成功：拉取云端库 ↔ 本地库按 id 合并（并集）→ 写回本地并推送合并结果到云端
→ 之后库的每次变更（入库/删除/导入）防抖 800ms 自动推送云端
→ 退出登录：保留本地库，停止同步
```

- **降级**：未配 `VITE_TCB_ENV` 或未登录 → 纯本地模式（现状不变）；云端拉取/推送失败 → 本地仍可用，界面提示一次。
- 页头账号区：未登录显示「登录云账号」链接；已登录显示用户名 + 「退出」。

## 4. 控制台配置步骤（教师/部署者执行）

1. [cloud.tencent.com](https://cloud.tencent.com) 开通**云开发 CloudBase**，新建环境（按量计费有免费额度），记录**环境 ID**；
2. 环境 → 身份认证 → 登录方式：开启**用户名密码登录**；
3. 数据库：新建集合 `symbol_libraries`，权限改为「自定义安全规则」，填入 §2 的规则；
4. 环境 → 安全配置 → **安全域名**添加 `hqj00.github.io`（以及 localhost 用于本地调试）；
5. GitHub 仓库 → Settings → Secrets and variables → Actions → **Variables** → 新建 `VITE_TCB_ENV` = 环境 ID
   （VITE_ 变量是构建期公开值，放 Variables 而非 Secrets 即可；`.env` 不入库，CI 构建从仓库变量注入）；
6. `git push` —— GitHub Actions 自动重新构建部署，几分钟后 Pages 站点即出现注册/登录入口。

## 5. 环境变量

| 变量 | 说明 |
|------|------|
| `VITE_TCB_ENV` | CloudBase 环境 ID（前端构建期变量；不含任何密钥，CloudBase 前端 SDK 本就设计为公开调用，权限由安全规则兜底） |

## 6. 验收用例

| # | 操作 | 期望 |
|---|------|------|
| 1 | 未配 VITE_TCB_ENV 启动 | 应用正常工作，页头显示「登录云账号」 |
| 2 | 注册新账号并登录 | 页头显示用户名；云端集合出现该 uid 的文档 |
| 3 | A 账号入库符号 → 退出 → 登 B 账号 | B 看不到 A 的符号（安全规则隔离） |
| 4 | 登录前本地有 3 个符号，云端有 2 个不同符号 | 登录后合并为 5 个，云端同步为 5 个 |
| 5 | 登录状态入库新符号 | 约 1s 后云端文档更新（防抖） |
| 6 | 断网登录 | 提示云端不可用，本地模式正常 |

## 7. 演进

- 教师端：只读拉取本班所有学生的符号库（另开管理员安全规则或云函数聚合）；
- 符号库容量：单文档有大小上限，超出时提示导出备份（现状提示沿用）；
- 登录态持久化由 SDK 处理（localStorage 存凭据），长期免登。
