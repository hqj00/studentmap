7. 符号设计链路

7.1 五步向导与数据模型

符号设计向导把课程要求拆成五步，一次只展示一步；前置条件不满足时不能进入下一步。五步是：需求定义 → iconfont AI 素材 → Illustrator 精修 → 上传与校验 → 入库。第 2、3 步是外部工具操作，本应用只提供描述词、操作清单与承接入口。

type SymbolCategory = 'point' | 'line' | 'area'
type SymbolSource =
  | 'iconfont-ai' | 'iconify' | 'illustrator' | 'other'

interface SymbolRecord {
  id: string          // 时间戳 36 进制 + 随机后缀
  name: string
  category: SymbolCategory
  tags: string[]
  svg: string         // 已通过规范化校验的 SVG 文本
  source: SymbolSource
  createdAt: number
}

符号库存于 localStorage 的 studentmap.symbols.v1。五步向导与智能符号页共享同一个 store，因此从任一入口入库的符号都会出现在两处。新增记录时 id 由时间戳与随机数组成，避免同一毫秒内连续入库冲突。

7.4 Iconify 检索与中文词库

iconfont 没有公开搜索 API（2026-10 实测：/api/icon/search.json 返回站点 HTML 壳，带反爬组件），因此应用内搜索改用 Iconify 公共 API。它免密钥、CORS 开放，静态托管也能直接用。

GET https://api.iconify.design/search?query=gas%20station&limit=48
GET https://api.iconify.design/tabler/gas-station.svg

中文描述先经过本地词库转换：命中词条返回英文检索词；未命中则原样搜索，并提示“可换用地物名词”。

词库 35 条常见地物（加油站、医院、学校、银行、车站、火车站、机场、公园、商场、超市、酒店、餐厅、咖啡、邮局、书店、图书馆、博物馆、体育馆、药店、警局、消防、停车场、厕所、景区、桥、隧道、水库、工厂、教堂、寺庙、气象台、地铁、灯塔、港口、长城）。匹配按对象顺序取第一个命中，因此存在子串关系时以先出现者为准：例如“火车站”会先命中“车站”。这是词库顺序的已知行为，不是搜索失败；需要精确结果时直接输入英文检索词。

候选网格用 <img> 直引 SVG URL，点选后才拉取 SVG 文本做校验。这样浏览 48 个候选不会触发 48 次完整下载与解析，只有在“真的要入库”时才付出校验成本。

7.5 入库、导入与合并

导入他人分享的符号库 JSON 时，不能信任文件内容。流程是：JSON 解析 → 必须是数组 → 逐条检查字段完整性 → 对每条 SVG 重新执行 checkAndNormalizeSvg → 跳过错误记录 → 按 id 去重 → 合并。

返回结果包含 added 与 skipped 两个计数：跳过包括字段缺失、SVG 校验失败、id 重复三类。非法 JSON 或非数组直接失败，原库不改动。导入时重新校验 SVG 是必要的——分享文件可能被手工编辑过，不能因为“它来自本应用”就跳过安全入口。

7.6 安全边界

符号缩略图用 v-html 渲染，因此只允许通过校验的 SVG 进入这个通道。校验器拦截脚本元素、foreignObject 与外部 http(s) 引用，能挡住最常见的 XSS 与“离线符号偷偷联网”两类问题。

但这不是完整的 SVG 白名单过滤：事件属性（如 onload）、javascript: 伪协议、CSS url() 等并未逐项剥离。课程场景默认符号来源可信（自己设计、Iconify 开源图标、同学分享），导入陌生人文件前应自行确认来源。若未来面向公网收集符号，需要补一层严格的白名单/消毒库，而不是继续加正则。

8. 账号与云端同步

8.1 CloudBase 注册三步

新版 CloudBase 不允许“用户名 + 密码”直接注册，注册必须走邮箱验证码三步：

const v = await auth.getVerification({ email })
const { verification_token } = await auth.verify({
  verification_id: v.verification_id,
  verification_code: code,
})
await auth.signUp({
  email, verification_code: code, verification_token, password,
  name, ...(username ? { username } : {}),
})

注册成功后 SDK 自动登录。登录用 auth.signIn({ username, password })，username 可填邮箱、用户名或学号（前端已归一化）。登录态由 SDK 存在 localStorage，长期免登。

8.2 账号归一化

服务端对用户名有强制正则：^[a-z][0-9a-z_-]{5,24}$。中文、大写开头、纯数字都会被拒。前端在注册与登录两侧做同一转换：

因此学号 20230101 注册时实际用户名是 s20230101，登录时输入 20230101 也会转成同一个值，学生无感。用户名是可选字段：只填邮箱也能注册，之后用邮箱登录；填了用户名，则邮箱与用户名指向同一个 uid。

8.3 数据模型与权限

集合 symbol_libraries，一个用户一条文档，_id = uid：

{
  "owner": "<uid>",
  "symbols": [ SymbolRecord, ... ],
  "updatedAt": 1718000000000
}

权限选“读取和修改本人数据 [PRIVATE]”，由数据库安全规则保证学生之间互不可见。前端通过 @cloudbase/js-sdk 直连，SDK 设计为公开调用，前端不持有密钥；真正的隔离在服务端规则，不在前端代码。

9.2 输出契约

推荐只接受知识库内的 id；模型给出未知 id 时该条被丢弃，不会让前端渲染一个不存在的投影。模型给出的参数合并进 typicalParams，但如前所述，尚未进入 effectiveParams。

{
  "recommendations": [
    { "id": "albers-equal-area-conic",
      "reason": "中国全图统计专题：面积严格相等……",
      "params": { "centralMeridian": 105,
                  "standardParallels": [25, 47] } }
  ]
}

教学助手的动作是白名单：setRegion、setProjections、setOverlays、setMarker、reset。未知识别、非法投影 id、越界经纬度在 sanitizeActions 与 applyActions 两层被丢弃；全部丢弃时按离线解析处理。

{
  "reply": "已切换到全球并对比墨卡托与等地球。",
  "actions": [
    { "type": "setRegion", "presetId": "world" },
    { "type": "setProjections", "a": "mercator", "b": "equal-earth" },
    { "type": "setOverlays", "tissot": true }
  ]
}

9.3 JSON 容错解析

模型偶尔会在 JSON 前后加解释文字或代码围栏。解析策略是：先找第一个 {，从那里截断；标准 JSON 解析失败时，再找最后一个 }，解析前缀；仍失败就抛错，由调用方降级。

这不是“宽容解析器”，只是对付尾随文字的最小容错。真正的合法性仍由 JSON.parse 与后续 schema 校验决定；解析成功但结构不对，同样降级。

9.4 超时预算

慢模型与中转站的首字可能超过 60 秒，因此超时不是“几秒”，而是一条分层预算：前端等 125 秒，代理等上游 115 秒，前端必须比代理长，才能在代理返回 504 之前拿到结构化错误。
