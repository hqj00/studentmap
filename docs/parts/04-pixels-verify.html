10. 从经纬度到屏幕像素

10.1 四层坐标

一个点从经纬度到屏幕，经过四层坐标。把层分清，才能解释“为什么放大后点不会跑、为什么框选得到的是经纬度、为什么导出的 SVG 比屏幕清晰”。

10.3 缩放、标记与比例尺

缩放只改变 SVG 组变换，不重算投影。以指针为不动点的公式见式 (19)。三类元素的行为不同：

  • 地图内容（球面、陆地、经纬网、Tissot、标记点、经纬度标注）：在变换组内，随缩放一起放大；
  • 整饰层（指北针、图例）：在变换组外，位置与大小不变；
  • 比例尺：在变换组外，但长度按当前倍率 重算式 (18)，所以标注的千米数始终正确。

“允许拖动”开关默认关闭。关闭时滚轮与拖拽都不生效，只能用右上角 ＋/－/重置按钮；开启后才允许指针捕获拖拽与以指针为中心的滚轮缩放。这样浏览 36 幅总览时不会因为误拖而把图面移出视野。

10.5 执行顺序与边界

  1. 由区域与投影计算 effectiveParams；
  2. 创建 d3 投影，定向（rotate / center），clipExtent(null)，fitExtent；
  3. 生成球面、陆地、经纬网、范围框、Tissot 路径；
  4. 生成经纬度标注、比例尺换算、图例数据；
  5. 渲染为 SVG；
  6. 用户缩放 / 平移时只改变外层 <g transform>，不重跑 2–4；
  7. 框选时走小地图自己的等距圆柱反算，不经过预览投影。

边界：预览的坐标单位不是米，不能拿 SVG 像素直接当平面坐标；比例尺只在投影中心附近可信；标记点与经纬度标注会随缩放变大，是“地图内容”，不是固定屏幕符号。需要固定屏幕尺寸的符号时，应放在整饰层而不是地图层。

11. 数值方法与异常处理

11.1 空值与有限性

投影计算可能返回 NaN、Infinity 或抛异常（极点、奇异区、proj4js 不支持的投影）。所有转换入口统一做有限性检查，失败返回 null，由界面显示“不支持”或省略该点，而不是把 NaN 写进 SVG 路径。

反算同样处理：框选点先夹取到合法范围，再四舍五入；试算输入先检查 Number.isFinite，否则提示“请先输入 X / Y”。

11.4 性能预算

  • 规则引擎：纯内存计算，目标小于 100ms；实际只做几次三角函数与排序，远低于预算。
  • 预览：18 幅总览 × 陆地 / 经纬网 / 整饰，全部本地 SVG；没有瓦片请求，首屏不依赖网络。
  • AI：前端 125s、代理 115s；超时即降级，不阻塞页面其他功能。
  • 构建：vue-tsc --noEmit + Vite 生产构建，2026-10-21 实测 2020 个模块、约 20–26 秒完成。

12.3 未覆盖与已知限制

  • 没有浏览器端到端自动化：本机 IAB 环境下点击、打字、上传事件不送达页面，只有导航、读取、截图可用。因此 UI 验证以模块测试 + 离线渲染 + 手工回归为主，不把“输入不生效”误判为应用 bug。
  • AI 依赖上游：2026-10-21 曾出现中转站账号组级 RPM 限流（429），线上自动降级为规则引擎；换供应商后恢复。限流不是前端 bug，但会改变用户看到的结果来源。
  • proj4js 能力边界：温克尔三重不支持试算；其他投影以运行时为准。页面不预先列出“全部支持”，避免承诺过期。
  • SVG 校验不是完整白名单：拦截脚本、foreignObject、外部 http(s) 引用，但未逐项剥离事件属性与伪协议；导入陌生人文件需谨慎。
  • AI 参数未接入有效参数：见 §3.6 与 §14.4。
  • 不做基准转换：WGS84 / CGCS2000 / GCJ-02 / BD-09 的差异不在本应用处理；需要合法测绘成果时使用法定软件与数据。
